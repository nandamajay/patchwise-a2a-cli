PatchWise A2A_CLI

Autonomous Builder-Reviewer loop for Linux patch review, lore intake, findings gating, and respin generation.
Roles: Chanakya + Aryabhatta
Mode: Local / Resume / Lore
Outputs: Findings + HTML + Respin

Problem

Manual patch babysitting is slow and inconsistent. A2A automates round-by-round review while preserving evidence and human auditability.

Agents

  • Chanakya (Builder): Applies fixes, references exact lines, reports residual risks.
  • Aryabhatta (Reviewer): Adversarial validation, concrete findings, no unsupported LGTM.
  • Orchestrator: Session lifecycle, findings tracking, policy enforcement.

Hard Gates

  • LGTM blocked when open findings exist.
  • Reviewer self-consistency guard blocks contradictory LGTM.
  • Optional: checkpatch/static-analysis gates.
  • Worktree lock avoids concurrent corruption.

How To Run

a2a loop --task <name> --watch-path /abs/path --max-rounds 3

a2a loop --task <name> --lore-url "https://lore.kernel.org/all/<msgid>/"

a2a loop --session <session-id>

./run.sh <lore-url|msgid|session|path>

Pipeline

InputLocal patch, lore URL/msgid, or session resume
→
Session InitCreate/update session metadata and round context
→
Builder RoundFix patch, emit evidence + residual risks
Validation GateSchema + checkpatch/static checks
→
Reviewer RoundRaise/close findings with location + action
→
LGTM GateBlock on open/new/inconsistent findings
PassLGTM + session report + optional auto-respin vN+1
↔
FailInject prior findings/comments and continue next round
→
StopMax rounds or operator decision
