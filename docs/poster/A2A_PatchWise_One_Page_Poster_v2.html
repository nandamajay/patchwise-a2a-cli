PatchWise Agent2Agent (A2A) Review

Aim: convert patch review from manual babysitting to autonomous, evidence-backed rounds with strict LGTM safety gates and resumable execution.
Builder: Chanakya
Reviewer: Aryabhatta
Driver: a2a CLI Orchestrator

What A2A Solves

  • Stops repeated restart-from-round-1 cycles.
  • Maintains prior findings and round context.
  • Prevents silent/unsafe LGTM decisions.
  • Creates audit trail for every decision.

Tasks Covered

  • Patch/lore intake and round orchestration.
  • Builder fix generation and patch updates.
  • Reviewer findings with severity and evidence.
  • Validation gates (schema/checkpatch/static).
  • Auto-respin (vN -> vN+1) and reports.

Building Blocks

  • Session manager (`.a2a/sessions`).
  • Artifact engine (`.a2a/reports`, `.a2a/logs`).
  • Findings lifecycle (open/new/resolved/closed).
  • Worktree lock and concurrency guard.
  • Lore ingestion + prior comment mapping.
  • Email bridge (optional remote operation).

Call Flow

1. InputLocal patch path, lore URL/msgid, or existing session.
→
2. Session InitLoad config, task, round budget, prior context.
→
3. Builder RoundApply fixes, explain rationale, publish residual risks.
4. Validation GateSchema + optional checkpatch/static checks.
→
5. Reviewer RoundEmit structured findings and verdict.
→
6. LGTM GateBlock if open findings or inconsistent reviewer reasoning.
7A. PassLGTM -> summary + HTML report + optional next-version patch.
↔
7B. FailInject findings into next round and continue.
→
8. Stop RulesMax rounds/time budget/operator stop, then resumable.

Execution Commands

a2a loop --task <name> --watch-path /abs/path --max-rounds 3

a2a loop --task <name> --lore-url "https://lore.kernel.org/all/<msgid>/"

a2a loop --session <session-id>

./run.sh <lore-url|msgid|session|path>
