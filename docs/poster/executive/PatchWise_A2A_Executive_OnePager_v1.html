PatchWise A2A - Executive One-Pager

Purpose

PatchWise A2A automates patch review cycles using two agents (Builder + Reviewer). The goal is faster turnaround, consistent review quality, and predictable execution.

What Was Built

  • Intake block for local patch, lore link/msgid, or session resume.
  • Round orchestration: Builder -> Validation -> Reviewer -> Gate.
  • Quality gates: findings validation + LGTM safety checks.
  • Context continuity: prior findings/comments reused each round.
  • Reporting: per-round and session-level artifacts.
  • Respin support: next version generation (vN -> vN+1).
  • Operational safety: worktree lock and optional email bridge.

Existing Paths Used

  • .a2a/sessions/<session-id>.json
  • .a2a/logs/<session-id>/
  • .a2a/reports/<session-id>/
  • .a2a/reports/<session-id>/session-report.html
  • .a2a/patches/<session-id>/vN/
  • .a2a/locks/worktrees/

Executive Call Flow

Input -> Session Init -> Builder Round -> Validation Gate -> Reviewer Round -> LGTM Gate -> (Pass: Finalize + Report + Respin) / (Fail: Next Round)

Business Value

  • Lower review cycle time through autonomous iteration.
  • Better review consistency and decision clarity.
  • Less rework from persistent session context.
  • Improved handoff with complete artifacts.

Primary Use Cases

  • Pre-submit kernel patch quality gate.
  • Lore review triage and response prep.
  • Session handoff and interruption recovery.
  • Remote control via email bridge.
  • Patchset coherence checks across versions.
